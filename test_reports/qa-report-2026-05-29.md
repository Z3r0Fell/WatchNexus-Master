## Critical Issues (Must Fix Before Shipping)

### C-01: [REGRESSION/SECURITY] Incomplete Cookie Auth Migration
**File**: `frontend/src/context/AuthContext.js` (lines 19, 52, 66, 77, 91)
**Issue**: AuthContext.js stores JWT in `localStorage` and sets `Authorization: Bearer` header, completely bypassing the httpOnly cookie auth that the backend now issues. The cookie is set by the server on login, but the frontend never reads from it. This means:
- The JWT is still XSS-exposable via localStorage
- Two auth mechanisms run in parallel (confusing)
- `axios.defaults.headers.common['Authorization']` overrides cookie-based auth

**Fix**: 
1. Remove all `localStorage.getItem('token')` and `localStorage.setItem('token')` from AuthContext.js
2. Remove `axios.defaults.headers.common['Authorization'] = 'Bearer ' + token`
3. Rely on httpOnly cookie sent automatically by the browser
4. Add `withCredentials: true` to all axios configs
5. Use `/api/auth/me` (cookie-based) to validate session on page load instead of reading localStorage

### C-02: [PERFORMANCE] React.lazy Not Used
**File**: `frontend/src/App.js` (lines 11-78)
**Issue**: All 30+ pages are eagerly imported. The `lazy` and `Suspense` imports exist on line 8 but are never used.
**Fix**: Convert all `import { X } from './pages/X'` to `const X = lazy(() => import('./pages/X'))`. Wrap routes in `<Suspense fallback={<Loader />}>`.

### C-03: [PERFORMANCE] AuthContext Missing Memoization
**File**: `frontend/src/context/AuthContext.js` (lines 63-96)
**Issue**: `login`, `register`, `logout` are recreated on every render. The context value object is never memoized, causing all consumer components to re-render on every state change.
**Fix**: Wrap functions in `useCallback`. Wrap `<AuthContext.Provider value={useMemo(...)}>`.

### C-04: [SECURITY] CSRF Protection Missing
**File**: `src/watchnexus/core/Program.cs`
**Issue**: Cookie-based auth without CSRF protection. SameSite=Strict helps but is not sufficient for all scenarios.
**Fix**: Add anti-CSRF token generation (e.g., double-submit cookie pattern) or validate `Origin`/`Referer` headers on mutating requests.

### C-05: [SECURITY] Refresh Tokens Stored in Plaintext
**File**: `src/watchnexus/core/Auth/AuthService.cs` (line 91-92)
**Issue**: Refresh tokens stored as-is in the Settings table. Database compromise reveals all active refresh tokens.
**Fix**: Store SHA-256 hash of refresh token. Use `FirstOrDefaultAsync` matching against hash.

### C-06: [UNIT TESTS] No Test Infrastructure
**Issue**: Zero test files across the entire project. No C# test project, no Jest config, no Playwright config.
**Fix**: Create test infrastructure with at minimum: (a) xUnit project for AuthService, Fortress, CellarController; (b) Jest/RTL for AuthContext, LicenseContext, TierGate; (c) smoke verification in CI.

### C-07: [ACCESSIBILITY] Widespread Missing aria-labels and Form Associations
**Issue**: Icon buttons, form inputs, and dynamic content lack proper ARIA attributes. This is a legal/compliance risk for enterprise deployment.
**Fix**: Add `aria-label` to all icon-only buttons. Add `htmlFor`/`id` pairs on all form inputs. Add `aria-live="polite"` to toast and loading regions.

### C-08: [LOAD] Sync-over-Async in Startup
**File**: `src/watchnexus/core/Program.cs` (line 283)
**Issue**: `.GetAwaiter().GetResult()` on the startup path blocks the thread. If database is slow or corrupted, the entire startup hangs.
**Fix**: Make the startup sequence properly async or use a background startup task.
