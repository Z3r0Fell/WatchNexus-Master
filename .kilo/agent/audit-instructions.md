# Full Code Audit Instructions

## Purpose
These instructions govern the full code audit workflow for any project. They must be followed exactly when an audit is ordered.

## Audit Requirements
When ordered, a full code audit must be a **character-by-character, line-by-line check** on every file in the project. It must be extensive, comprehensive, and absolute to verify the project is working correctly.

## Execution
- Spin up to **10 agents** to complete the process.
- Ensure all cross-checks coincide with each other and nothing is missed.
- Each agent must audit its assigned section thoroughly and report all findings.

## Reporting
Once the audit is complete, display **any and all issues** found for review. Issues must be categorized and prioritized.

## Fix Protocol
- If a full fix order is requested, **all items will be corrected** without stopping or requesting further information.
- After all fixes are completed, **automatically commit the files to GitHub**.

## Changelog & Versioning
- In the app, under **Help > About**, there is a changelog section.
- This area must be updated with **all fixes applied** for tracking purposes and user transparency.
- Version numbering: each new fix release increments by one (e.g., 1.0.1, 1.0.2, 1.0.3, etc.).
- The changelog entry must include the version number, date, and list of all fixes applied.

## Scope
These instructions apply to **any project** being worked on, regardless of language, framework, or platform.
